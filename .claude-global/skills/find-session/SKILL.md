# find-session

## Overview

過去セッションの所在を特定し、**resume** するか**中身だけ取り出して今のセッションで使う**。
検索・一覧化・resume コマンド生成は `scripts/find-session.py` が決定的にやる。
Claude の仕事は「依頼を検索語に言い換える」「候補を依頼と照らして絞る」の2つだけ。

## データの所在（スクリプトが扱う。手で grep しない）

| ソース | 期間 | 中身 |
|---|---|---|
| 要約 `~/.nb/claude/sessions/日付/*.md` | 2026-06 以降すべて | 意図・作業内容・結論。セッション終了時に生成 |
| jsonl `~/.claude/projects/*/<id>.jsonl` | 直近約1か月だけ | 会話全文。これが残っているものだけ resume できる |

- 要約はセッションを閉じるまで作られない → 閉じていないセッションは jsonl 側にしか無い
- jsonl のユーザー発言は `y` ばかりで中身はアシスタント側とタイトルにある。スクリプトはタイトル・両者の発言・コマンド引数を対象にし、ツール入出力と実行中の自セッションは除外する

## 手順

```bash
F=~/.claude/skills/find-session/scripts/find-session.py
python3 -I $F search "語A|言い換えA" "語B|言い換えB"   # 1. 要約を検索
python3 -I $F search --transcripts "語A|..." "語B|..."  # 2. 要約で0件/的外れのときだけ（約8秒）
python3 -I $F show <id先頭8桁>                          # 3. 要約本文・cwd・resume コマンド
python3 -I $F excerpt <id> "語|..."                     # 4. 要約に無い細部を会話本文から抜く
```

**検索語の組み方**: 引数どうしは AND、`|` は OR。依頼から論点を2〜3個に分け、各論点を言い換えで OR に広げる。

- 要約はユーザーの言い方ではなく作業の言葉で書かれている。症状なら原因側・設定名側の語も入れる
  （例「JSESSION が無くてログインできない、原因は Apache」→ `"JSESSION|Cookie|401|ログイン" "Apache|httpd|ProxyPass|ProxyErrorOverride"`）
- PR/Issue 番号は4桁以上なら数字だけを1グループにする（`#1063`・`PR 1063`・`/pull/1063` の表記揺れを吸収）。3桁以下は日付や件数に当たるので `"#50|pull/50|PR 50|PR50"` のように接頭辞付きで書く
- 全条件一致が多すぎたら AND を1つ足す。0件なら出力の「一部一致」を見て、どの語が外れたかで言い換える
- 2〜3文字の英字略語（`RC` 等）は単語の一部（`source`）に当たるので、正式名（`Rocket`）で書く
- 照合は部分一致（正規表現ではない）。大文字小文字・全角半角は無視される。`excerpt` も同じ

## 候補の出し方

依頼と照らして上位3〜5件に絞り、1件1〜2行で出す。`日付 | プロジェクト | id先頭8桁 | resume可否 | なぜ候補か`。
並び順は依頼との一致度で決める。スクリプトの hits 順は語の出現回数でしかなく、関係の薄いセッションが上に来ることがある。
意図の行だけで判断がつかないものは `show` で本文を読んでから並べる。確信が持てる1件があればそれを先頭に。

依頼の中の具体（「〇〇の話」）がセッションに見つからなければ、見つからなかったと言い、近い記述を示してユーザーに確認する。近い話を依頼の話として答えない。

## 選ばれた後

依頼に「続きやりたい」等があればすぐ下の表で判断する。「どれ？」だけなら候補を出して止まり、どうするかをユーザーに聞く。クリップボードに入れるのは resume が決まってから。

| 状況 | 勧めること |
|---|---|
| resume 可 かつ その作業の続きをやりたい（後でやる前提で止めていた等） | resume |
| 知りたいのは結論・手順・設定値など一部だけ | 中身の取り出し |
| resume 不可（jsonl 削除済み） | 中身の取り出しのみ |

- **resume**: `show` が出した `cd <cwd> && claude -r <id>` を `win32yank.exe -i` でクリップボードへ。command-handoff ルールの例外で `!` は付けない（今の Claude のプロンプトで実行すると Claude の中に Claude が起動するため。新しいペインで貼ってもらう）。cwd が消えている警告が出たら伝える
- **取り出し**: 要約本文から依頼に関係する部分だけを今の会話に出す。要約に無い細部（コマンド・設定値・エラー文）は `excerpt` で会話本文から抜く。jsonl が無ければ要約が唯一のソースだと明示する

## よくある間違い

| 間違い | 正しくは |
|---|---|
| `~/.claude/projects` を直接 grep する | 1か月より前は消えている・ノイズが多い。まず要約を `search` |
| `rg` で要約を探す | `.dotfiles-*.md` 等ドット始まりの要約が隠しファイル扱いで漏れる。スクリプトを使う |
| ユーザーの言葉そのままで1語検索 | 論点ごとに言い換えて OR、論点間を AND |
| agent-memory の記述を現状として出す | 古いことがある。セッション要約の結論を優先し、食い違いは指摘する |
