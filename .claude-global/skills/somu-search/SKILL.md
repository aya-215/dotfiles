# somu-search

## Overview

総務パック（ミラー）の eB-API を直接叩いて、ボリュームを丸ごと手元に保存し、その中を文字列で検索する。
規定の本体のように中身が添付にしかないときは、添付を取りに行ってテキストにする。

`eb-api-somu` MCP の検索（getItems 系）と `getFileText` は、ログインセッションが無いため 401 になる。このスキルでは MCP を使わない。

## 手順

```bash
S=~/.claude/skills/somu-search/scripts/somu.py

python3 -I $S volumes 規定          # 1. ボリュームを名前で探す（語を省くと全部）
python3 -I $S search 204 テレワーク  # 2. AND 検索。初回はそのボリュームを全件取って保存する
python3 -I $S files 204 <item_id>    # 3. 本文が添付にあるときだけ、添付の一覧を見る
python3 -I $S text 204 <item_id>     # 4. 添付をテキストにする（file_id を並べて絞れる）
```

- ボリュームIDは `204` のようにゼロを省いてよい。
- 0件なら語を減らすか言い換える。それでも無ければ別のボリュームを当たる。
- 検索は全項目が対象。全角と半角、大文字と小文字は区別しない。値が語と完全に一致したレコードを先頭に出す。IP を調べるときはこれで本人が先頭に来る。
- `search` は既定で20件まで出す。足りなければ `--limit N` を付ける。
- 項目名を知りたいときは `specs <vol>` を使う。

### よく使うボリューム

| ボリューム名 | 用途 |
|---|---|
| □社内IPアドレス管理 | サーバーや PC の IP、PC名、設置場所、OS、MAC アドレス。内部と外部の IP が別々のレコードになっていることがある |
| ■社内規定 | 規則。レコードには概要しか無く、本体は添付（PDF / Word）にあることが多い |
| ルールDB | 社内開発のノウハウ。タイトル、用途、内容など |
| □サーバー管理 | 顧客サーバーの設定情報 |

ID は `volumes <名前の一部>` で引く。

### 件数が多いボリューム（終了コード 3）

1万件を超えるボリュームは、全件を取る前に `CONFIRM: ... 件ある` を出して止まる。
件数をユーザーに伝えて了承を得てから `--yes` を付けて実行し直すこと。勝手に `--yes` を付けない。

## 読み方の注意

- 接続先はミラーなので、本番より遅れていることがある。
- 保存したデータは自動では更新しない。結果が古い・おかしいと思ったら `--refresh` で取り直す。見出しに「いつ時点のデータか」が出る。
- 規定はレコードの改定日と添付の版が食い違うことがある。たとえば改定日は新しいのに、添付の PDF は古い版のまま。添付のコメント（更新日）も見て、どれが最新かを答えに添える。
- `files` では旧版（コメントに old を含むもの）を後ろに並べる。`text` も既定では旧版を読まない。旧版も読むなら `--old` か file_id を指定する。
- 回答には、根拠にしたレコードの詳細 URL を添える。
- サーバーの共有フォルダ（`\\host\c$` など）を直接探しに行かないこと。本番相当のストレージに負荷がかかる。添付は `text` で1件ずつ取る。

## スクリプトが止まったとき

| メッセージ | 対処 |
|---|---|
| `.mcp.json に eb-api-somu の ... が無い` | `~/.dotfiles/.mcp.json`（gitignore 済み）に eb-api-somu の `ebase-api-url` と `ebase-viewer-url` を書く。値は kintai-check と共通 |
| `eB-API に接続できへん` / `添付のサーバーに接続できへん` | 社内ネットワークか VPN に繋がっているか確認する。一時的な詰まりのこともあるので、一度はそのまま再実行する。途中で止まっても前回の保存データは壊れない |
| `WARN: <型> の N〜M件目 を飛ばした` / 検索の見出しに「取れへんかった部分あり」 | その範囲の値が欠けている。0件や見当たらない結果を「無い」と答える前に `--refresh` で取り直す |
| `この形式はテキストにできへん` / `テキストにできへんかった` | 旧形式の .doc / .xls や、中身が壊れた添付。URL をユーザーに渡して開いてもらう |
| `（添付を取れへん（HTTP 404）: ...）` | その添付だけリンク切れ。ほかの添付は続けて読んでいる |

dotfiles は PUBLIC なので、接続先・IP・item_id をこのスキルに書かないこと。
