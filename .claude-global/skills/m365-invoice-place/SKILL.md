# m365-invoice-place

## Overview

田中(一)さんから引き継いだ定例作業。**Microsoft 365 Copilot ライセンスの請求書を毎月、
管理部の共有フォルダへ設置する**。毎月15日が請求日で、設置は請求日の2〜7日後で足りている。

役割分担は固定:

| 担当 | 内容 |
|---|---|
| **ユーザー** | 管理センターを普段の Chrome で開いて請求書PDFをDL（Windows の Downloads へ） |
| **スクリプト** | 検証 → リネーム → 共有フォルダへコピー → 転送後に照合 |
| **Claude** | スクリプトを叩いて結果を伝える。**判定はしない** |

## 最重要: Claude は判定しない

`scripts/m365-invoice-place.sh` が全部のガードを持っている。**Claude が「たぶんこのPDFで合ってる」と
判断してはいけない。** スクリプトを通さずに `Copy-Item` で直接置くのは禁止。

スクリプトが決定的に保証すること:

- 商品名 `Microsoft 365 Copilot` の明細行で請求書を判別（「Copilot」の語だけだと他の請求書も通る）
- **請求書発行日をPDF本文からパース**してファイル名を生成。15日でなければ停止
- 同名ファイルがあれば **exit 1。上書きは絶対にしない**（経理が処理済みのファイルを壊さないため）
- コピー後にサイズ＋SHA256で照合

## 手順

### 1. ユーザーがDL済みか確認する

DL前なら、ユーザーに管理センターからDLしてもらう。**Claude がブラウザを開く必要はない**
（Playwright 不採用の理由は下記）。DL先は Windows の Downloads。

### 2. ドライランで内容を見せる

```bash
# 引数なしなら Downloads の最新PDFを自動で拾う
/home/aya/.dotfiles/scripts/m365-invoice-place.sh

# ファイルを指定する場合
/home/aya/.dotfiles/scripts/m365-invoice-place.sh <PDFのパス>
```

出力に「設置名」「コピー先」が出る。**この内容をユーザーに見せて確認を取る。**

### 3. 承認を得てから実コピー

```bash
/home/aya/.dotfiles/scripts/m365-invoice-place.sh <PDFのパス> --commit
```

共有フォルダ＝自分のマシンの外なので、**`--commit` は必ずユーザーの承認を得てから実行する**
（`.claude-global/rules/external-actions.md`）。

### 4. 結果を伝える

設置後、担当範囲はここまでであることを添える。
`斎部経費レコード登録済/` への移動は経理側の作業。

## スクリプトが停止したときの読み方

| メッセージ | 意味 | 対処 |
|---|---|---|
| `Copilot の明細が見つからん` | DLしたPDFが別の請求書 | **ユーザーに指摘する。** 同名の課金アカウントが2つあるので取り違えの可能性。管理センターで選び直してもらう |
| `同名ファイルが既にある` | その月は設置済み | 重複作業。設置済みである旨を伝えて終了 |
| `発行日が15日ちゃう` | 請求日の規約が変わった可能性 | 勝手に進めず、ユーザーに判断を仰ぐ |
| `請求書発行日をPDFから取得できへん` | PDFの書式が変わった | スクリプトの正規表現を直す必要がある。手動設置に切り替えるか相談 |
| `共有フォルダに到達できへん` | ネットワーク/VPN | 接続を確認。作法は `wsl-unc-access` スキル |

## 設定

| 項目 | 値 |
|---|---|
| 設置先 | `\\kanri-yayoi-svr\共有\法人名義カード使用履歴\インボイス(領収書)eBASE\AUTO-000011215_マイクロソフト_Microsoft365Copilotのライセンス` |
| ファイル名 | `AUTO-000010660_YYYYMMDD_Microsoft365Copilotのライセンス.pdf` |
| AUTO番号の上書き | 環境変数 `M365_INVOICE_AUTO_NO` |

> **フォルダ名は `AUTO-000011215` だがファイル名は `AUTO-000010660`。これは誤記ではなく実際そうなっている。**
> 「揃えよう」としないこと。ただし**経理には未確認**で、`旧：AUTO-000010660_` フォルダの存在から
> 10660 が旧コードである可能性が残っている。番号を変える必要が出たら環境変数で差し替える。

## Playwright を使わない理由

この環境の `browse-with-playwright` は **WSL側に専用ブラウザを立てる方式**
（`~/playwright-browsing/profile`）で、普段使いの Windows Chrome には原理的に接続できない
（`--remote-debugging-port` は起動時にしか指定できないため）。

結果、Playwright 経由だと **Microsoft への再ログイン（MFA）が毎月必要**になり、手動DLより遅い。
同名の課金アカウントを取り違えるリスクは、スクリプトの `Microsoft 365 Copilot` 明細判定で
機械的に検出できるので、目視選択でも安全性は担保されている。
