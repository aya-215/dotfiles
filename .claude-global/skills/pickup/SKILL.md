# pickup

## Overview

探すのは `scripts/find_handoff.py` が決定的にやる（番号の表記揺れ吸収・番号ごとの検索・段階的に広げる）。
Claude の仕事は「候補が複数なら選んでもらう」「読み込んで、PR・issue の最新状態と照合して示す」「ユーザーの指示どおり続ける」の3つ。

引き継ぎメモは書いた時点の状態でしかない。PR のマージ状態・レビュー・後から付いたコメントは、メモから再開する前に必ず一次情報で確かめる。

## 手順

1. 探す（引数はユーザーが渡したものをそのまま。URL・指示の言葉が混ざっていてよい）:
   ```bash
   python3 -I ~/.claude/skills/pickup/scripts/find_handoff.py <引数...>
   ```
   出力は JSON: `results` の配列。要素ごとに `term`・`stage`・`hits`（`path` / `summary` / `created` / `status`）。
   - 引数に PR・issue 番号（URL・`#1236`・`eae#134`・`No7400` 等）があれば、番号ごとに別々に探して1要素ずつ返す。このとき「マージされた」等の言葉は指示とみなして検索に使わない
   - 番号が無ければ、言葉が全部入っているメモを探して1要素で返す
   - `stage` は `handoff-open` → `handoff-all` → `work-in-progress` → `all` → `none` の順に広げ、最初に当たった段
2. 番号ごとに結果を分ける:
   - `none`: その番号の引き継ぎは無い。全部 `none` なら `find-session` スキルで過去のセッションを探すことを提案する
   - 1 件: そのファイルを読む
   - 複数: 題名（`summary`）・日付・状態を並べ、どれを読むかユーザーに選んでもらう
   - `stage` が `handoff-open` 以外: 待ち中の引き継ぎではなく、終わった引き継ぎや他のメモに当たったことを一言添える
   - 別々の番号が同じメモに当たったら、1回読めばよい
3. **最新状態を確かめる（必須・要点を示す前にやる）**: 読んだメモに出てくる PR・issue すべてについて、`gh`（GitBucket なら `mcp__gitbucket__*`）で次を取る。
   - 状態（open / merged / closed）・マージ日時・レビュー状態
   - **メモの `created` / `updated` より後に付いたコメント**（本文まで読む。誰かからの依頼・追加の要望が入っていることがある）
   - ユーザーが「マージされた」と言った PR が実際には未マージなら、先にそう伝える
4. 読んだら、待っていたもの・今の状態・次にやることを短く示す。3 で分かったメモとの食い違い（未マージ・新しいコメント・既に済んでいた作業）を先頭に書く。
   - 「元のセッション」の作業場所が今の作業ディレクトリと違えば伝える
   - 文脈が足りないときは、記載の `claude --resume <ID>` で元の会話に戻れることを示す
5. ユーザーの指示（「マージされたから残作業調べて」等）に従って続ける。投稿・close 等の外部アクションの文案は、3 で読んだ最新コメントを踏まえて作る。
6. その件が片付いたら、引き継ぎメモの frontmatter を `status: resolved` に書き換える（ファイルは消さない）。
