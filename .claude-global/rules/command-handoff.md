# ユーザーにコマンド実行を依頼するときはクリップボードに入れる

auto mode でブロックされたコマンドや対話ログインが必要なコマンドなど、ユーザーに実行を依頼する場合は、
本文にコマンドを示すだけでなく、そのコマンドを Windows のクリップボードにも入れておくこと。
ユーザーが手でコピーする手間を省くため。

```bash
printf '%s' "$(cat <<'EOF'
! <実行してほしいコマンド>
EOF
)" | win32yank.exe -i
```

- `win32yank.exe` を使う（`clip.exe` は日本語が文字化けする）
- 末尾の改行は入れない（貼り付けた瞬間に実行されるのを防ぐ）。上の `$(...)` で除去される
- 先頭に `! ` を付けて入れる（Claude Code のプロンプトにそのまま貼って実行できるように）
- 複数コマンドを依頼する場合は、1回で貼って実行できる形（`&&` 連結など）にまとめて入れる
- 返答では「クリップボードに入れた」と一言添える
- worktree の中のセッションでは `!` も本体に向けた git を止められる。本体向けのコマンドは自分で ExitWorktree（keep）して打つ（`rules/worktree.md` の「仕上げ」）。どうしてもユーザーに頼むなら、別のペインで打つ前提で `!` を付けずに入れる

## 手順そのものを最小にする

ユーザーに実行してもらう手順（本番・検証機への配置や確認）は、ユーザーの手作業と判断の数が最小になる形にする。

- 「ファイルを置いて画面で確かめる」だけで済むなら、それを第一案にする
- 手で確かめる段が要るなら、自動で確かめる形に置き換えられないかを先に考える
- コピー元・コピー先のパス、使うアカウント、確認する URL・画面を書いて、実行中に聞き返さずに済むようにする
