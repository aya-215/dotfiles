# コードコメント規約

## 分量

- 1つの意図は1行で書く。前置き・言い換え・段階的な説明を重ねない
- 複数行のブロックコメントは、制約が実際に複数あるときだけ
- 周辺コードのコメント密度に合わせる。既存コードにコメントが無い箇所へ新規に足さない

## 内容

非自明な WHY だけを書く。隠れた制約・workaround を入れた理由・読み手が驚く挙動といった、
コードから復元できない情報に限る。

書かないもの:

- WHAT（コードを読めば分かること。`// ユーザーIDを取得する` の類）
- 変更履歴（「〜を追加した」「旧実装では〜だった」等）
- チケットID参照（`(ABC-123)` 等）

例外: 公開API・関数・モジュールの docstring は利用者向け仕様なので WHAT を書く。
