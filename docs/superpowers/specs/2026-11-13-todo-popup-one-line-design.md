# TODO ポップアップを1行1タスクで見せる（設計）

## 目的

tmux の TODO ポップアップ（`C-q t`、幅60%）で `~/memo/todo.md` を開くと、1行に題・key のリンク・`— next:` が入っていて情報量が多く、頭に入らない。
「1行の簡潔なタスクの説明がずらっと並ぶ」見た目にする。

## 現状の問題（スクショで確認）

- `wrap` のままなので、長い行が画面の端で単語の途中から折り返される（「選択肢バ／ブル」）
- conceal で隠した URL・タグも折り返し幅に数えられ、隠した分だけ空白の行ができたり、`→ next` が次の行に押し出されたりする（確認待ちのタグ、rc: の長い URL）

## ゴール / 非ゴール / アンチゴール

- ゴール: やる・待ちの各タスクが1画面行に収まり、題だけが並ぶ。カーソルを置いた行だけ key と next が読める
- 非ゴール: グルーピング（ユーザーが「todo リストとしては微妙」と判断）、やるの行の整理（別の作業）、完了欄の表示（下にあって目に入らないので今のまま）
- アンチゴール: `todo.md` の形式や AI 側スクリプト（apply.py 等）に手を入れること。平日朝の無人 `/todo` を止めるリスクを負わない

## 方式の検討

| 方式 | 内容 | 判断 |
|---|---|---|
| A 見た目だけ変える | nowrap にし、カーソル以外の行は key と next を隠し、カーソル行の下に詳細を仮想行で出す | **採用**。nvim 側（`lua/todo`）だけで済み、50〜80行規模 |
| B ファイル形式を変える | next を子の行に分けて fold で開閉する | 見送り。todo_md.py・decisions.py/context.py（git 履歴の旧形式も読む必要）・core.lua の行移動・テスト約40か所・SKILL.md 2本で10ファイル・300〜500行。切り替え日に無人実行が止まるリスク。A で足りなければ再検討 |
| C 別の一覧ビュー | 題だけの一覧から Enter で元の行へ飛ぶ | 見送り。画面が2つになり編集の流れが変わる |

## 設計（A）

- `todo.md` を表示するウィンドウだけ `nowrap`（ウィンドウローカル）
- やる・待ち・完了のタスク行で、カーソル行以外は key のリンク（`[key](url)`）と `— next: …` を conceal で丸ごと隠し、題だけを見せる
- カーソル行（ノーマルモード）も同じく題だけにし、その直下に仮想行（extmark の `virt_lines`、ファイルには書かない）で `<key> → <next>` を薄い色（Comment）で1行出す。key も next も無い行は仮想行を出さない
- 挿入モード（render-markdown が conceallevel 0 にする）では今どおり生の行を見せ、仮想行も出さない
- 確認待ち欄の表示は今のまま（タグ隠し）。nowrap になることで隠したタグによる空白行が消える
- 人が書いた題の中の Markdown リンク（`[officeのteams資料修正](https://...)`）は今どおり URL 部分を隠す

## 決めたこと（Claude の判断）

- カーソル行も題だけにした。生の行を出すと nowrap で URL のぶん横に伸びるため
- 長い題は画面端で切れる（折り返さない）
- 仮想行の書式 `<key> → <next>` と色（Comment）

## 実装者に任せること

- conceal 範囲の計算（`core.conceal_ranges` の拡張か別関数か）と、既存の `→` 仮想文字の扱いの整理
- テスト（`config/nvim/tests/todo_core_spec.lua`）の追加範囲
