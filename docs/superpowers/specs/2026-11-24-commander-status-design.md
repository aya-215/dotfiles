# 司令塔「現在の状況をまとめて」設計（小さな変更）

作成: 2026-11-24。親の設計は `2026-11-24-commander-design.md`。11/24 に司令塔を実際に回し、状況確認を何度も手でやった中で決めた。

## 目的と理由

ユーザーは日中、定期的に「今どうなってる？」と司令塔に聞く。11/24 はそのたびに Claude が gh・tmux・引き継ぎメモ・到達性をその場のコマンドで調べ、遅く、結果もぶれた（tmux のサイドバーペインを読んでしまう罠も踏んだ）。
「返ってきたもの有る？」の上位互換として、1つの言葉で全部を調べ、司令塔ファイルを更新し、作業を分かりやすく出す。

## ゴール

「現在の状況をまとめて」で次を順にやる。

1. 全部を調べる
   - GitHub の PR・issue: 一覧（todo・引き継ぎメモ）に出てくるもの全部。状態・Approve・チェック・最新コミット・前回確認以降の相手の動き
   - GitBucket の PR: 同上（MCP）
   - Rocket Chat・メール: 待ちの相手からの返事＋自分宛てのメンション・DM の新着（前回確認以降）
   - tmux の各セッション: 作業中／ユーザーの返事待ち／閉じた
   - 引き継ぎメモ: 前回確認以降に書き換わったもの（status・最後の見出し）
   - 待ちがサーバーの起動のとき: 到達性
   - 動いている tmux セッションの作業場所の git: 未コミット・未 push
2. 司令塔ファイルを更新する（済んだこと・tmux・メモ・一覧・最終確認時刻）
3. 表示する（下の「表示の形」）

## 表示の形（ユーザー決定: 4案から C「ボールの持ち主ごと・1件1行」に列を足した C+）

コードブロックに入れ、桁をそろえる。1件1行のまま、右に「待ち時間・期限・何を止めているか」を足す（2行目の「次の一手」は付けない。ユーザー「C++ までは不要」）。

```
変わった  #1316・#1313 マージ ・ RDP 作業完了 ・ epc-1316 は閉じた

あなた    epc-1308   #1308 をマージする？（佐藤さんの確認を待つか）   25分  11/25  ← #1321・リリースが止まる
          hankyu-102 #102 のコメント投稿とマージは誰がやる？           4時間

          —          決める：AI参考情報の文言 ／ 👎 #1264             11/25  ← リリースの中身
          —          シフトオン本番リリース                            11/25  #1308・#1321 待ち
          —          玉木さん PR #131 のレビュー                       4日放置
          低         ほか5件

Claude    epc-1321   #1321 レビュー中

相手      畑上さん   P.11 のパック商品の扱い・送信用アカウント          11/20〜
          松本さん   ai-team-docs PR #103 のレビュー                    11/19〜  発表 11/30

新着      （Rocket Chat・メールの自分宛て。無ければ段ごと省く）
```

- 段: 変わった／あなた／Claude／相手／新着。空の段は省く
- 「あなた」は、上にセッションが返事を待っているもの（セッション名・返事を待たせている時間）、1行空けて自分から始めるもの（`—`）、最後に期限なしを「低 ほかN件」とまとめる（聞かれたら開く）
- 右の列: 待ち時間（セッションが止まってから）／期限（司令塔ファイルの期限・todo の next）／`←` で何を止めているか／放置日数（相手から来てから）。分からない列は空ける
- 「Claude」は作業中のセッション
- 「相手」は相手の名前ごとに1行。右に待ち始めた日と、関わる期限
- セッションの待ち時間は `status.py` が出す（Claude の画面に出る「done HH:MM」から計算）

## やらないこと

- 自動・定期の実行（cron・/loop・通知）。聞かれたときだけ動く（親設計の決定のまま）
- 新しく来た依頼を todo に書く（翌朝の `/todo` に任せる）
- 全 repo の git を見る（動いているセッションの作業場所だけ）
- 「返ってきたもの有る？」を残す。手順 3 は削除し、起動ワードからも外す（ユーザー決定。あまり使っていなかった）

## 失敗とみなすこと

- サイドバーペイン等、Claude 以外のペインを読んで状態を誤判定する
- 前回から変わったことが落ちる（今日の #1316 の Approve・#1313 のマージ・1254 の本番作業完了のような変化）
- Rocket Chat の秘密（API キー等）を要約・司令塔ファイルに書く（親設計の決まりのまま）

## 作り方の案（Approaches）

| 案 | 内容 | 取捨 |
|---|---|---|
| **A. `status.py` を1本足す（選択）** | gh・tmux・メモ・到達性・git を1回で JSON に。Claude は MCP（GitBucket・Rocket Chat・メール）と更新・表示 | 速く毎回同じ。罠をコードで潰せる |
| B. `collect.py`・`check_waits.py` を広げる | ファイルは増えない | collect の「開いたときの材料集め」の役目がぼやける |
| C. SKILL.md に手順を書くだけ | すぐ書ける | 毎回手でコマンドを組み、遅くぶれる。決定的処理の分離ルールに反する |

ユーザーは A を選んだ。

## 決めたこと（ユーザー）

- 「返ってきたもの有る？」の上位互換。全部調べ→メモ更新→分かりやすく表示
- 表示は「対応中／対応が必要／待ち」でまとめる
- 「返ってきたもの有る？」の手順と起動ワードは削除

## Claude の判断（ユーザーが確認できるよう明記）

- 最終確認時刻を司令塔ファイルに1行で残す（`最終確認: <ISO 日時>`、タイトル直下）。差分の基準にする。`status.py` が読んで `last_check` として返し、無ければその日の 0 時
- tmux の判定: `pane_current_command` が `claude` のペインを探す（ペイン番号では決め打ちしない）。下の数行に `esc to interrupt` があれば作業中、無ければ返事待ち。自分のペイン（`$TMUX_PANE`）は除く
- 引き継ぎメモの変化は、前回確認以降に更新されたファイル（mtime）で拾う。状態を別に保存しない
- 到達性は、待ち中の引き継ぎメモの `## 待っているもの` に出てくる IPv4 だけを、よく使うポート（22・80・445・3389）で 2 秒ずつ試す
- GitHub の取得は `check_waits.py` の `fetch` を使い回す。`returned` の判定も出す
- GitBucket・Rocket Chat・メールは MCP でしか見られないので Claude が見る。`status.py` は GitBucket の ref を「MCP で確かめる」として一覧に出すだけ

## ビルダーに任せること

- `status.py` の JSON の細かい形・テスト（既存の `scripts/tests/` に倣い、外部呼び出しは関数注入で差し替える）
- Rocket Chat で自分宛てメンションを取る方法（`search_messages` 等、MCP で使える手段を確かめて SKILL.md に書く）
- SKILL.md の手順 3 の書き換えと description の起動ワードの差し替え
