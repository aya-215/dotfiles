# 業務TODOをAIに管理させる 設計

- 日付: 2026-11-10
- 参考: しもち「タスク管理までAIエージェントに任せたら、確認待ちに答えるだけになった」(zenn.dev/rescuenow/articles/4c03a548cd6589)、同「2026年自分流AIエージェント環境構築の秋」(49826fc6cc2713)

## 意図

業務TODO（`~/memo/todo.md`、tmux `C-q t` のポップアップで開く）を、AI が書いて AI が動かすものにする。
今は全部手書きで、元の PR・Issue・発言へのリンクが無く、`/my-tasks` が見つけたものと食い違ったまま古くなる。
ユーザーの言葉: 「AIが書いてAIが動かすくらいのものが管理しやすいし陳腐化しないと思う」。

人の仕事は、todo.md の先頭に並ぶ「確認待ち」に答えることと、思いついたタスクを手で足す・手で完了にすることだけにする。

## 目標・非目標・アンチゴール

目標
- 業務タスクが、元のリンクと「次にやること（Next）」付きで todo.md に自動で載る
- 元が片付いたタスク（PR マージ・Issue close）は自動で完了に移る
- 判断が要るものだけが、番号付きの確認待ちとして先頭に並ぶ
- `/my-tasks` の誤判定を、使いながら見つけて直せる

非目標
- 私生活のタスク（`aya-215/life` の task Issue）。今回は触らない
- 記事の「司令塔が作業役（別の Claude Code）を起動して作業させる」部分
- 確認待ちを Claude の入力欄の上に出す mod（todo.md の先頭で足りる。必要になったら別件）

アンチゴール（動いても失敗とみなす）
- 人が手で書いた行・手で完了にした行を AI が消す、または未完了に戻す
- AI の過去の出力（todo.md 自体・前回の実行ログ）を、次の実行で一次データとして読む（`/my-tasks` が保存しない理由と同じ。推測が事実として戻ってくる）
- AI が外部アクション（PR コメント・Rocket Chat 送信・Issue 作成）を行う。確認待ちに答えても、外部への投稿はユーザーが別途承認する
- ポップアップで編集中の todo.md を AI が上書きして、人の編集が消える

## 記事から取り込むもの・取り込まないもの

| 記事 | この設計 |
|---|---|
| タスクごとの Next | 各行の末尾に `— next: …` |
| タスクごとの Log | 行には持たない。AI 実行ごとのコミットメッセージに理由を書き、`git -C ~/memo log` で追える（Claude の判断） |
| 起動時にマージ済みを完了に、新規レビュー依頼をタスク化 | 決定的スクリプト（GitHub 同期）＋ AI 取り込み |
| 突き合わせをサブエージェントに | 無人実行の `claude -p` が担う |
| 着手順: 待たせている人 → 期限 → 他の前提 | 「やる」セクションを AI がこの順に並べる |
| 確認待ち: 1行目に決めること、判断に要る事実、おすすめ付き選択肢 | 同じ書式 |
| レビュー指摘に N1, N2 と番号 | 自分の PR に付いた未対応のレビュー指摘は Next に `N1,N2 残` の形で出す |
| 答えたら記録と一覧からの削除は司令塔 | 次の実行（または `/todo`）で反映し、確認待ちから消す |
| 人に見せる前で止める | 既存ルール（外部アクション承認）で担保 |
| 作業役の起動・effort 選択 | 取り込まない |

## todo.md の形式

1タスク1行を保つ（`core.lua` が1行単位で動かすため。Next を子行にすると `<CR>` で Next だけ取り残される）。

```markdown
# TODO
<!-- ai-updated: 2026-11-11 07:00 -->

## 確認待ち
1. #1202 メール初期値の進め方を相談する？
   事実: 登録済みは710件(4.7%)、シフトオン系は全員空
   選択: A 相談する（おすすめ） / B そのままレビュー待ち
   回答:

## やる
- [ ] PR#1163 レビュー指摘対応 [epc#1163](https://github.com/...) — next: N1,N2 を直して push
- [ ] インターン資料修正

## 待ち
- [ ] PR#1202 レビュー待ち [epc#1202](https://github.com/...) — next: 彌永さんのレビュー

## 完了
- [x] ...
```

- 見出しは `## 確認待ち` → `## やる` → `## 待ち` → `## 完了`。現状の「見出しなしの未完了エリア」を `## やる` に変える（`core.lua` の `open_area_end` 等の修正が要る）
- 元リンク `[key](url)` の key がタスクの同一性の鍵。key の形式: GitHub は `<repo略称>#<番号>`、GitBucket は `gb:<repo>#<番号>`、Rocket Chat は `rc:<メッセージID>`、メールは `mail:<Message-ID の短縮>`
- 元リンクの無い行 = 人が書いた行。AI は文言を変えずに元リンクと Next を後ろに付け足すことはしてよい。見つからなければ触らない
- 確認待ちの番号は実行ごとに振り直す。「回答:」の後ろにユーザーが書き込む（ポップアップで編集可）
- 完了セクションは肥大化する。30日より古い完了行は `~/memo/todo-archive/YYYY-MM.md` へ移す（決定的スクリプト）

## 仕組み

決定的な処理と AI の判断を分ける。

### 1. 決定的な部分（スクリプト、AI を使わない）

- **GitHub 同期** (`todo-sync-github`): todo.md の元リンクのうち GitHub/GitBucket のものの状態を取得し、MERGED/CLOSED を完了へ移す。cron で頻繁に回してよい（例: 平日 8〜20時 毎時）
- **適用器** (`todo-apply`): AI が出した変更案（JSON）を受け取り、todo.md に反映する唯一の書き込み口。検証すること:
  - 非空行が減らない（完了アーカイブ以外）
  - 元リンクの無い行の文言が変わっていない
  - 人が完了にした行を未完了に戻していない（直前のコミットとの比較で判定）
  - 違反したら書かずに終了し、ログに残す
- **編集中の保護**: ポップアップの nvim が todo.md を開いている間は書かない。nvim 側で開いている間ロックファイル（例 `~/memo/.todo.lock`）を置き、スクリプトはロックがあれば書かずに次回へ回す
- **コミット**: AI 由来の書き込みは `todo(ai): <要約>` でコミットし、本文に変更ごとの理由と根拠リンクを書く。人の編集は今の `todo: 日時` のまま。これで人の訂正と AI の変更を git で区別できる

### 2. AI の判断（無人実行）

- cron で `claude -p` を起動（平日朝、例 7:00）。既存の `claude-summarize` と同じく `--settings '{"disableAllHooks":true}'` で hook の再帰発火を防ぐ
- 手順:
  1. `/my-tasks` の収集・判定ロジックでタスク候補を出す（出力は構造化 JSON。各候補に key・タイトル・自分ボール/他人ボール・元URL・Next・根拠の抜粋）
  2. 現在の todo.md と key で突き合わせて変更案（追加・待ちへ・やるへ・完了へ・Next 更新・並べ替え・確認待ち）を作る。todo.md は重複検出と人の行の把握にだけ使い、タスクの根拠にはしない
  3. 確認待ちに「回答:」が書かれていれば、それを反映した変更案を作り、その項目を確認待ちから消す
  4. 変更案を `todo-apply` に渡す
- 確認待ちに出すのは: 方針の選択、人に見せる前のもの、ユーザーにしかできない手作業、AI と人の判断が食い違うもの（例: 人が完了にしたが元の PR がまだ open）
- 実行ログ（`/my-tasks` の生 JSON・変更案・適用結果）は `~/.local/log/todo-ai/YYYY-MM-DD/` に置く。次回の実行はこれを読まない

### 人の判断の記録（蒸し返し・取り合いの防止）

- `todo-apply` と GitHub 同期は、人の判断を `~/memo/todo-decisions.jsonl` に追記する（1行1判断: key・判断の種類・日時・理由）。記録するのは、確認待ちへの回答と、AI/同期の移動を人が戻したこと（git 履歴で `todo(ai)` / 同期コミットの後に人のコミットが逆の移動をしたもの）
- このファイルは人の入力の記録なので「AI の過去出力を読まない」の例外として、AI 実行と同期スクリプトが読む。同じ key・同じ種類の問いは、一次データの状態が変わるまで確認待ちに出さない。人が戻した key は、同期スクリプトが自動で動かさない
- 書くのは決定的スクリプトだけ。AI は直接書かない

### 行の出どころと key

- 行が AI 由来か人由来かは、git の由来で決める（その行を最初に入れたコミットが `todo(ai)` か `todo:` か）。リンクの有無では決めない（人が `[text](url)` で書いた行が既にある）
- 人由来の行: AI はセクション移動・完了化・リンクと Next の付け足しをしてよい（ユーザーの「基本全部触っていい」）。タイトルの文言は書き換えない
- key は一次データの ID から作る。Rocket Chat は `rocketchat.sh` が出す `_id` を使い、1発言に複数の作業があれば `rc:<_id>#1`・`#2` と枝番を振る。worktree の未コミット差分は `wt:<worktree名>`
- 日報・セッション要約にしか根拠が無い候補は、一次データ（RC・Issue・PR 等）まで遡れたものだけ載せる。遡れないものは確認待ちに「これはタスク？」として1回だけ出し、答えを判断の記録に残す

### 3. 手動の入口

- `/todo` スキル: その場で 2 の手順を対話セッションで回す（無人実行を待たずに反映したいとき、回答を即反映したいとき）

## /my-tasks を使いながら直す

`/my-tasks` は動作がまだ怪しい部分がある前提で組む（ユーザー指示）。

- **評価データの自動収集**: AI の変更（`todo(ai)` コミット）の後に人が手で戻した・消した・書き換えたものを、git 履歴から決定的に抽出する（例: AI が足した行を人が消した、AI が完了にした行を人が戻した、AI が待ちにした行を人がやるに戻した）
- **週次の見直し**: 抽出結果を一覧にし、原因を `/my-tasks` の3層（取得層・判定層・解釈層、agent-memory `scripts/task-inventory-verification-gate.md`）に振り分けて、スキルやスクリプトを直す。既存の `/retrospective` に相乗りするか別スキルにするかは builder に任せる
- 直した結果は次の週の訂正件数で確かめる

## 制約

- `~/memo` は remote の無いローカル git。クラウドルーティンからは書けないので、AI の実行はローカルの cron＋`claude -p`
- `claude -p` の課金: ユーザーは「クレジット消費にはなっていないはず」と認識。agent-memory には 6/15 から Agent SDK クレジット化とあり食い違う。実装の最初に1回小さく回し、使用量の画面で確かめる
- gh はアカウント使い分けが要る（`ebase-dev/*` は eBASE-Mori、`GH_TOKEN` 未指定は無言でアクティブアカウントに落ちる）
- `/my-tasks` は1回約8分・Rocket Chat だけで 50k tokens 超
- `core.lua` の行喪失ガードと同じ方針（行が減る変更は止める）を適用器でも守る
- コメント・コードは既存の規約（`.claude-global/rules/code-comments.md`）に従う

## 決まっていること（ユーザーの決定）

- 対象は業務だけ。台帳は `~/memo/todo.md`
- AI は todo.md を基本的に全部触ってよい。形式も扱いやすく変えてよい
- 人も手で追加・完了を続ける。人が完了にしたものは人の判断を優先する
- 確認待ちは todo.md の先頭に出す
- AI の判断は無人実行（cron）
- `/my-tasks` は使いながら最適化していく
- Rocket Chat・メール由来など機械的に完了を判定できない行: 決着（「対応しました」等）が読めたら AI が完了へ移す（誤りは人が戻し、評価データになる）。決着も進展も見えないまま14日経った行（`/my-tasks` の窓から外れる）だけ、確認待ちに「まだ要る？」と出す
- `claude -p` が課金対象だった場合の扱いは、そのとき金額を見て決める。計画では、課金の確認を無人実行の作り込みより前に置く

## Claude の判断（ユーザーは未確認）

- Log は行に持たず、AI コミットのメッセージで代える
- 1タスク1行・`— next:` 区切り・`[key](url)` の書式
- 完了は30日でアーカイブ
- GitHub 同期は毎時、AI 実行は平日朝1回
- 回答はポップアップで「回答:」に書く。`/todo` でも即時反映できる
- ロックファイルで編集中の上書きを防ぐ
- 人の判断は `todo-decisions.jsonl` に決定的スクリプトが記録し、蒸し返し・同期との取り合いを防ぐ
- 行の出どころは git の由来で判定。人の行のタイトル文言は書き換えない
- 一次データまで遡れない候補は確認待ちに1回だけ出す

## builder に任せること

- スクリプトの言語（既存の `scripts/` に合わせて bash か python）と置き場所
- `/my-tasks` の出力を JSON にする方法（スキルを分けるか、出力モードを足すか）
- 並べ替えの細かい規則（同順位のときの並び）
- 週次見直しの実装形態
- 既存の todo.md（未完了11件・待ち3件・完了約60件）の新形式への移行手順
