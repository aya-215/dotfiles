# commander の「終わった会話」を、司令塔の Claude が一覧へ漏れなく反映できる形にする

## 何のため

`status.py` の `ended_sessions`（前回の確認以降に終わった会話の要約の結論）は、11/25 の事故を防ぐために足した（2026-11-25-commander-ended-sessions-design.md）。事故の中身は、本番 00002 の確認が別のセッションで済んでいたのに、一覧に「未確認」が残ったこと。

その後わかったこと:

- ユーザーはこの表示を読まない。司令塔の Claude が状況を管理するための材料である（ユーザー）
- 同じ tmux の会話は大半が別の作業だった（80組・つなぎ目190本のうち167本）。tmux ごとにまとめると成果が落ちる。tmux 名は作業を表していないことが多い
- 1回の確認で出る件数は、日中は中央値2件、多いときで6件、最大11件
- PR・issue 番号での突き合わせでは、きっかけの件が拾えない。要約からは `eae#142` しか取れず、一覧の「本番 00002 の項目確認」の行には番号が無かった

## 決めたこと（ユーザー）

- 司令塔の Claude は、結論を一覧と引き継ぐ欄に書き換えて反映し、変えたことを報告する（例: 一覧の項目を「済み（0件）」にする）。違っていればユーザーが「〇〇まだ」で戻す
- 定型作業のような、わざわざ出す意味の無い軽い会話は「ほかN件」に畳んでよい
- 作り方は B: 材料を足したうえで、全件を必ず処理させる

## 検討した道

| 案 | 中身 | 採否 |
|---|---|---|
| A. 材料を足して全部 Claude が見る | 会話ごとに結論・cwd・番号を出し、Claude が反映する | 不採用。件数が多い回に1件を素通りしても気付けない |
| B. A に加え、全件の処理を数えられる形にする | 会話1件ごとに「反映した」か「関係なし」を必ず付け、件数を表示する | 採用。11/25 の事故は「会話の結果を当てなかった」ことなので、照合の精度より漏れの無さが効く |
| C. 番号が一致した組だけをスクリプトで候補にする | 会話と一覧の行を共通の番号で結ぶ | 不採用。きっかけの件を拾えない |
| tmux ごと・同じ作業ごとにまとめる | 1行に縮める、最後の1件だけ出す等 | 不採用。77/80組で成果が落ちる。「続き」は1割で、飛び飛びに出ることもある |

## 作り方

### status.py（決定的）

`ended_sessions` の要素を次にする。`end` の昇順は変えない。

- `session_id`・`tmux`・`window`・`pane`（map.tsv の `END` 以外の最後の行から。引けなければ `tmux` は今までどおり cwd のフォルダ名で、`window`・`pane` は null）
- `cwd`（要約の frontmatter）
- `refs`: `## 意図` と `## 結論` から `refs.refs_in_text` で取った番号。加えて、リポジトリ名の無い `#1254` を cwd のリポジトリで補う（cwd が ebase-portal-chat の clone か worktree なら `epc#1254`）。リポジトリを決められなければ補わない
- `end`・`conclusion`・`path`（今までどおり）
- `alive` は外す（名前の一致しか見ておらず、同じ tmux が別作業の寄せ集めなので意味が無い）

除外と重複の直し:

- 司令塔自身の除外を、tmux 名からペインの座標に変える。`TMUX_PANE` の `session_name`・`window_index`・`pane_index` と、会話の `tmux`・`window`・`pane` が全部一致するものだけを除く。今は司令塔が共用の tmux（例: dotfiles-ebapi）で動くと、そこの別作業の会話が全部消える
- まだ続いている会話を除く。その session_id の transcript（`~/.claude/projects/*/<session_id>.jsonl`）の最後の user/assistant の記録の時刻が、要約の `end` より5分以上新しければ、続いている（21時の backfill が開いたままの会話を要約した）とみなして出さない。ファイルの更新時刻は使わない（閉じたときに away_summary・cost-state 等が足されるため。実装時に判明）会話が終われば SessionEnd が要約を作り直すので、そのときに出る。`wsl --shutdown` で落ちた会話は transcript が `end` のまま止まるので出る
- 確認の途中に書かれた要約が2回出ないよう、要約の更新時刻の上限を `now`（`last_check` になる値）にする

### SKILL.md（Claude の手順）

「現在の状況をまとめて」の手順に次を足し、今の「1行に縮めて出す・判定はしない」を置き換える。

- `ended_sessions` の1件ごとに、必ず次のどちらかを決める
  - 反映した: 一覧・引き継ぐ欄のどの行をどう変えたか（済みにした・状態を書き換えた・メモに足した）。手がかりは `refs`・`cwd`・結論の中身。番号が無くても中身で当てる
  - 関係なし: 定型作業や一覧に無い作業。worktree の作成・整理、週報・勤怠、動作確認など
- 司令塔ファイルの更新（手順4）で反映を書き込む
- 表示は「変わった」段に、反映したものを1件1行（作業の場所＝cwd のフォルダ名と、何を変えたか）で出す。最後に「終わった会話 N件（反映 a・ほか b）」を出し、a＋b が N になるようにする
- 反映は確認を求めずに行う。ユーザーが「〇〇まだ」と言えば戻す（既存の 4.「〇〇止まった」の流れ）

```
変わった  epc#1316 マージ
          ebase-portal-chat  一覧「本番 00002 の項目確認」を済み（0件）にした
          pilot_webcatalog   引き継ぐ欄のメモに「160.92 の送信確認は成功」を足した
          終わった会話 6件（反映 2・ほか 4）
```

## 作る人に任せること

- cwd からリポジトリを決める方法（git の remote を見る・フォルダ名の決まりで引く等）。cwd が消えている場合は補わない
- transcript を引く方法と、5分の幅の置き場所
- テストの組み立て（`tests/test_status.py` の `EndedSessionsTest` に足す）
