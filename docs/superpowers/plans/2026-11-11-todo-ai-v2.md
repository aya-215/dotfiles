# 業務TODOのAI管理 v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 試運転の照合結果（F1〜F6 と細かい直し）を、/todo・/my-tasks・apply.py に入れ、ユーザーが指示して直す `/todo-edit` と意図の記録を足す。

**Architecture:** 書き込み口は引き続き apply.py だけ。ユーザー指示の変更は新しい source `user` として apply を通り、各 op の意図を todo-decisions.jsonl に `intent` として残す。PR のボール判定（F1）と課題DB の取得（F5）は決定的なスクリプトにし、LLM はその出力を読む。

**Tech Stack:** Python 3 標準ライブラリ（unittest）、curl、gh、Claude Code スキル。

**Spec:** `docs/superpowers/specs/2026-11-10-todo-ai-management-design.md`（末尾「追補 2026-11-11」）

## Global Constraints

- v1 の Global Constraints（`docs/superpowers/plans/2026-11-10-todo-ai-management.md`）はすべて有効
- 新しい key 形式: 課題DB `ebpm:<課題No>`（例 `ebpm:No00007400`）。URL は `https://ebpm.ebase-jp.com/ebase-web-v3/DispDetail.do?volumeName=02043&itemID=<item_id>`
- 課題DB は読み取りのみ。`http://192.168.234.19:8080/ebase-net/eb-api` に POST（`text/plain; charset=utf-8`）、curl で、1回30件まで、呼び出しの間は1秒空ける、並列にしない
- コミット件名: ユーザー指示の変更は `todo(user): <要約>`（origin 判定では人の行扱い）
- 意図の記録: `{"ts", "ref", "kind": "intent", "value": <意図の文>, "by": "human"}`（任意で `"prev_ref"`）
- テスト: `python3 -m unittest discover -s scripts/todo-ai/tests`（既存 186 件を壊さない）。~/memo・~/.local/log には触らない

## Review Focus

1. source `user` の追加で、ai/sync の保護（完了から戻さない・人のタイトルを変えない）が緩まない（Task 1）
2. 意図のある行を、/todo（source ai）が意図に反して完了・削除・上書きしない（context に必ず出て、SKILL が読む）（Task 2, 6）
3. 課題DB が落ちている・遅いときに /my-tasks 全体が止まらない（sources_failed に入るだけ）（Task 4, 5）
4. PR のボール判定で、取得に失敗した PR を「待ち」と決めつけない（unknown を返す）（Task 3）
5. `ebpm:` key の追加で、既存の key 判定・同期・アーカイブが壊れない（Task 5）

### Task 1: apply.py に source `user`・意図の記録・件名の修正

**Files:** Modify `scripts/todo-ai/apply.py`, `scripts/todo-ai/decisions.py`; Test `scripts/todo-ai/tests/test_apply.py`, `test_decisions.py`

**Interfaces:**
- Produces: `SOURCES = ("ai", "sync", "user")`。source `user` だけが使える op: `edit_title`（`ref`, `title`）、`delete`（`ref`）、`note`（`ref` のみ。台帳は変えず意図だけ記録）。source `user` は 完了→やる/待ち の move を許す

- validate: source `user` のときだけ、`edit_title` で指定された行のタイトル変更と `delete` で指定された行の消失を許す。それ以外の保護は source によらず同じ
- コミット件名: 確認待ちの件数は `confirm` の件数で数える（試運転で件名「確認待ち1」・本文「19 件」）

### Task 3: PR のボール判定 `pr_ball.py`

**Files:** Create `scripts/todo-ai/pr_ball.py`; Test `scripts/todo-ai/tests/test_pr_ball.py`

**Interfaces:**
- Produces: `decide(pr: dict, me: set[str]) -> dict`（`{"ball": "mine"|"theirs"|"done"|"unknown", "reason": str}`）。`pr` の正規化形: `{"state": "open"|"closed"|"merged", "author": str, "reviewers": [str], "events": [{"user": str, "ts": ISO8601, "kind": "comment"|"review", "state": "APPROVED"|"CHANGES_REQUESTED"|"COMMENTED"|null}]}`
- 規則（上から最初に当たったもの）: closed/merged → done／author が me でない → unknown（この判定は自分の PR 用）／reviewers が空 → mine「レビュアー未設定」／me 以外の events が無い → theirs「反応待ち」／最後の event の user が me → theirs／それ以外 → mine（bot も相手に数える）
- Produces: CLI `pr_ball.py github <repo略称>#<n>`（gh で取得。`ebase-dev/*` は eBASE-Mori のトークン、PATH は sync_github の `ensure_gh_path` を再利用）、`pr_ball.py --from-json`（標準入力の正規化 JSON。GitBucket は /todo・/my-tasks が MCP の読み取りで集めて渡す）。出力は1行 JSON。取得失敗は `unknown`（exit 0、stderr に理由）
- me: `{"eBASE-Mori", "森彪人", "mori.a"}`（環境変数 `TODO_ME` で上書き可、カンマ区切り）

- [ ] **Step 1: テスト**: 規則の各行、bot が最後なら mine、取得失敗は unknown（gh をモック）
- [ ] **Step 2:** FAIL → 実装 → OK → コミット `feat: 自分の PR のボールを決める pr_ball.py を追加`

### Task 4: 課題DB の読み取り `ebpm_issues.py`

**Files:** Create `scripts/lib/ebpm_issues.py`; Test `scripts/todo-ai/tests/test_ebpm_issues.py`（fixture XML。ネットワークに出ない）

**Interfaces:**

  - comments: 自分が登録した `since` 以降のコメント（課題No・課題名・item_id・日時・本文）
  - notices: お知らせ先担当者が自分の `since` 以降のコメント（登録者も）
  - assigned: 担当者名が自分で状況が完了系でない課題（課題No・課題名・状況・item_id）
  - 接続できない・タイムアウト → `failed` に理由を入れて exit 0（/my-tasks の sources_failed に `ebpm` を入れるため）
- 読み方は release-skills-repo の `period-export-tool/scripts/IssueLink.ps1`（`/mnt/d/git/release-skills-repo`）と agent-memory `ebase-web/ebpm-issue-db-02043-eb-api.md` に合わせる。自分の名前（コメント登録者・担当者名に入る表記）は実装時に読み取りで確かめ、既定値にする

- [ ] **Step 1: テスト**: XML 解析・期間の絞り込み・failed の扱い（fixture）
- [ ] **Step 2:** FAIL → 実装 → OK

### Task 6: `/todo` の規則を直す

**Files:** Modify `.claude-global/skills/todo/SKILL.md`

- F2: 他人担当は add しない／F3: is_task の「追加」は候補の ball が theirs なら待ちへ

- 自分の PR の ball は `pr_ball.py` の結果に従う
