## 3. 設定を変える場合（パターン B / C）

### 前提: 課金アカウントの種類を先に見る

**MOSA か MCA かで操作画面が全く違う。** まずここを確認する。

```
管理センター > 課金情報 > 課金アカウント > (アカウントを選択) > 種類
```

> 「eBASE株式会社」という同名の課金アカウントが2つある。請求書の内容で見分ける、と引き継ぎでは
> 言われているが、**自動化では目視判定を使わない**。アカウントID か、PDF 中身の
> `pdftotext | grep Copilot` で機械的に判定すること。

### PDF 添付を ON にする

| 種類 | 手順 |
|---|---|
| **MOSA** | `課金情報 > 請求のお知らせ` → 「通知設定の編集」 → **請求書PDF**の「請求書メールにPDFを添付する」にチェック → 保存 |
| **MCA** | `課金情報 > 課金アカウント` → アカウント選択 → **課金プロファイル**タブ → プロファイル選択 → 「請求書と支払いの連絡先設定」の**設定の管理** → 「メール添付で請求書を受け取る」を **オン** → 保存 |

必要な権限: MOSA なら全体管理者（課金管理者でも可）／ MCA なら課金アカウントの所有者か共同作成者。

### 受信者に自分を追加する（パターン C）

受信者は**ロールで自動的に決まり、デフォルト受信者を外すことはできない**:

- **MOSA** → 組織内の全**全体管理者・課金管理者**の primary + alternate アドレスへ送信
- **MCA** → **Billing profile owner / contributor / Invoice manager** ロール保持者へ送信

任意アドレスの**追加は可能**。MCA なら
`課金プロファイル > 請求書と請求通知 > 追加の受信者` の「受信者の編集」から追加する。

> **「自分だけに飛ばす」は不可。** 他のロール保持者にも届き続ける。
> 止めるにはロール自体を剥奪するしかなく本末転倒なので、
> 「他の人にも届くが自分にも届く」状態で運用し、Thunderbird 側で振り分けて整理する。

## 4. 自動化のアプローチ（パターン A に入ってから）

### 本命: メール経由

1. 請求書メールが届く（PDF 添付付き）
2. Thunderbird のフィルタで専用フォルダへ振り分け（`thunderbird-config` スキル）
3. 添付 PDF を取り出す
4. `AUTO-000010660_YYYYMMDD_Microsoft365Copilotのライセンス.pdf` にリネーム（YYYYMMDD = その月の15日）
5. `powershell.exe` 経由で共有フォルダへコピー（`wsl-unc-access` スキル）

**判定は決定的に。** 「Copilot の請求書か」は `pdftotext | grep` で機械判定する。
LLM の「たぶんこれ」に任せない。

### 対抗: Azure Billing REST API

```
POST https://management.azure.com/providers/Microsoft.Billing/billingAccounts/{billingAccountName}/invoices/{invoiceName}/download?api-version=2020-05-01&downloadToken={token}
```

完全無人化でき、課金アカウントを**ID指定**できるので同名アカウント問題が原理的に消える。

**ただし MCA / Microsoft Partner Agreement 限定。MOSA では使えない。**
加えて Entra アプリ登録 + 請求書閲覧者ロールが必要で、情シス/管理部の承認が要る見込み。
→ §3 で MCA だと分かった場合のみ検討する価値がある。

### 保険: Playwright / Power Automate

- **Playwright**（`browse-with-playwright` スキル）: 確実に動くが MFA とトークン期限で半自動。UI変更で壊れる
- **Power Automate / Logic Apps**: 会社が既に契約しているなら。無いなら優先度低

### 実行タイミング

設置は請求日の2〜7日後で足りているので、「15日以降の初回PC起動時」程度のトリガで十分。
厳密な定時実行は不要。

## 7. 2026-09-16 半自動化フローで今月分を設置完了

**9月分は設置済み。** メール（暫定C＝未着）とは無関係に、管理センターからの手動DL経由で完了した。

### 確定した運用フロー（半自動）

| 担当 | 内容 |
|---|---|
| 人 | 管理センターを普段の Chrome で開いて請求書PDFをDL（Windows の Downloads へ） |
| スクリプト | 検証 → リネーム → 共有フォルダへコピー → 転送後に照合 |

```bash
scripts/m365-invoice-place.sh                 # Downloads の最新PDFをドライラン
scripts/m365-invoice-place.sh <pdf> --commit  # 実コピー
```

**Playwright 案は不採用。** この環境の Playwright は WSL 側に専用ブラウザを立てる方式（`~/playwright-browsing/profile`）で
普段の Windows Chrome には繋げないため、Microsoft への再ログイン（MFA）が毎月必要になる。
手動DLなら再認証ゼロ。同名アカウントの取り違えはスクリプトの `Microsoft 365 Copilot` 明細判定で検出できるので、
目視選択のリスクは機械的に潰せている。

### スクリプトが決定的に保証すること

- 商品名 `Microsoft 365 Copilot` の明細行で判定（「Copilot」の語だけだと他の請求書も通るため）
- **請求書発行日をPDF本文からパース**してファイル名を生成。15日でなければ停止
- 同名ファイルがあれば **exit 1。上書きは絶対にしない**（経理が処理済みのファイルを壊さないため）
- コピー後にサイズ＋SHA256で照合
- AUTO番号は環境変数 `M365_INVOICE_AUTO_NO` で差し替え可（既定 `AUTO-000010660`）

| 日付パース | 8月分 | `20260815` を自動抽出＝ハードコードでない |
| 壊れPDF / 不在ファイル | — | いずれも exit 1 |
